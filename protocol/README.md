# Blendcam protocol v1

Local network only. One port (default **52700**) is used for both UDP and TCP.
All messages are UTF-8 JSON. Both sides are tested against the files in `fixtures/`.

## Connect URL (QR code)

    blendcam://<host>:<port>?token=<token>

`token` is a random string generated by the add-on (kept in its preferences). Any UDP packet or TCP
session without the right token is ignored.

## Pose — phone → Blender, UDP, ~60 packets/s

One JSON object per datagram (`fixtures/pose_basic.json`, `fixtures/pose_limited.json`):

| field   | type            | meaning |
|---------|-----------------|---------|
| `v`     | int             | protocol version, always `1` |
| `seq`   | int             | increases by 1 per packet, restarts from 0 when the AR session restarts |
| `t`     | float           | phone time, seconds (`ARFrame.timestamp`) |
| `token` | string          | token from the QR code |
| `m`     | 16 floats       | ARKit camera transform (`ARCamera.transform`), **column-major** (m[12..14] = translation, metres) |
| `trk`   | string          | `normal` / `limited` / `notAvailable` |
| `joy`   | [float, float]  | joystick x (right +), y (forward +), each −1…1 |
| `lift`  | float           | height slider −1…1 (up +) |
| `focal` | float           | focal length, mm |
| `focus` | float, optional | focus distance, metres |

The receiver drops a packet whose `seq` is not greater than the last accepted one (late or reordered),
except when its `t` is newer than the last accepted one (the AR session restarted and `seq` began
again from 0). After such a restart Blender re-anchors, so the camera stays where it is.
`focal` = 0 means "not set": Blender keeps the camera's lens.

## Control — TCP, both directions

Newline-terminated JSON objects, each with a `type`.

Phone → Blender:

| type           | fields | |
|----------------|--------|-|
| `hello`        | `token`, `device` | must be the first message, within 3 s; a new valid `hello` replaces the previous client |
| `anchor`       | — | bind the current phone pose to the current camera pose (heading + position only) |
| `record_start` | `t` | phone time when recording starts (sent after the 3-2-1 countdown) |
| `record_stop`  | — | |
| `play` / `pause` | — | timeline playback |
| `frame`        | `n` | jump to frame `n` |
| `settings`     | `scale`, `smooth`, `joy_speed`, `roll_deg` (0/90/180/270), `mirror_x` (bool), `stream` (bool), `preset` (`handheld`/`steadicam`/`crane`/`tripod`/`custom`), `roll_lock` (bool), `orbit` (`off`/`target`/`turntable`), `orbit_hold` (0–1), `stream_quality` (`normal`/`high`) | any subset |

Blender → phone:

| type    | fields |
|---------|--------|
| `state` | `connected`, `recording`, `frame`, `frame_start`, `frame_end`, `fps`, `focal`, `camera`, `take` (next or current take name) + optional `last_take`, `scale`, `smooth`, `joy_speed`, `roll_deg`, `mirror_x`, `stream`, `live` (false = a take is shown, the phone does not drive the camera), `preset`, `roll_lock`, `orbit`, `orbit_hold`, `stream_quality`, `target` (orbit target name or empty) |
| `toast` | `text` (short message shown on the phone) |
| `frame` | `len`, optional `ts` — followed by exactly `len` bytes of JPEG (live camera view) |

## Coordinates

ARKit world: right-handed, +Y up (`worldAlignment = .gravity`); the camera looks along its local −Z.
Blender world: +Z up. Mapping: `blender = C · arkit`, `C` = +90° rotation about X,
i.e. a point `(x, y, z)` becomes `(x, −z, y)`. Blender cameras also look along local −Z with local +Y up,
so the camera orientation needs only the same change of basis.
